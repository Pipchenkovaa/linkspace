# Диагностика

Краткая памятка по типовым проблемам при локальном запуске LinkSpace.

| Признак | Что проверить |
| --- | --- |
| `address already in use` | Порт 8000 занят: остановить старый сервер (`lsof -i :8000`, затем `kill <PID>`) или запустить API с `--port 8001`. |
| `command not found: uvicorn`, `No module named 'fastapi'` | Активировать окружение `source .venv/bin/activate` и установить зависимости. |
| `externally-managed-environment` при `pip install` | `pip` запущен вне `.venv`: активировать виртуальное окружение. |
| `Connection refused` | Сервер не запущен или работает на другом порту. |
| Ответ `422` | Запрос не прошел валидацию; причина указана в поле `detail` ответа. |
| Пропали данные | Сверить `data_dir` в строке `Application started` с текущим `DATA_DIR`. |
| В интерфейсе «Эх, сервер не отвечает...» | Проверить `curl http://127.0.0.1:8000/health` и значение `NEXT_PUBLIC_API_URL`. |
| При работающем API браузер показывает CORS error | Адрес фронтенда должен входить в `CORS_ORIGINS`; это особенно важно, если Next.js запустился не на порту 3000. |
| Новый адрес из `.env.local` не применился | Перезапустить `npm run dev`. |

## Логи

Логи backend выводятся в терминал, где запущен Uvicorn. Сообщения приложения помечены `linkspace`.

Чтобы одновременно видеть вывод и сохранить его в файл:

```bash
uvicorn app_final:app --env-file .env 2>&1 | tee linkspace.log
```
