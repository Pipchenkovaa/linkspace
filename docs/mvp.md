# LinkSpace MVP

## О проекте

**Суть.** LinkSpace — сервис для сохранения и организации полезных ссылок.
Ссылки собираются в одном месте, распределяются по коллекциям, получают теги и
отметку «избранное», а потом быстро находятся через поиск и фильтры.

**Для кого.** Для тех, кто регулярно сохраняет статьи, документацию, инструменты
и учебные материалы и хочет держать их в структурированной библиотеке вместо
десятков открытых вкладок и неразобранных закладок браузера.

**Какую проблему решает.** Ссылку легко сохранить, но зачастую потом очень
сложно найти.

## Границы MVP

Входит: ссылки, коллекции, теги, избранное, поиск и фильтры, статистика
библиотеки.

Не входит:

- авторизация и несколько пользователей: сервис рассчитан на одного человека;
- автоматическое получение названия, описания и картинки сайта: пользователь
  вводит их сам;
- редактирование URL: другой адрес — это новая ссылка;
- корзина: удаление окончательное;
- пагинация: все ссылки отдаются одним списком;
- база данных: данные хранятся в JSON-файлах.

## Экраны

Интерфейс — одна страница. Коллекции, избранное и поиск не открывают отдельные
экраны, а меняют подборку ссылок на главном.

### 1. Библиотека

Главный экран со всеми ссылками.

- Шапка: логотип, индикатор API (`GET /health` раз в 30 секунд), поиск (клавиша
  `/` ставит в него курсор), кнопка «Добавить ссылку».
- Заголовок со статистикой: «15 ссылок в 6 коллекциях».
- Полка коллекций: папка на каждую коллекцию с числом ссылок, буквами доменов
  трех последних ссылок и названиями двух последних. Кнопка «+ Новая коллекция».
  Если папки не помещаются, полка прокручивается стрелками или свайпом.
- Переключатель «Все / Избранное».
- Теги текущей подборки с числом ссылок: первые 8, остальные под «Еще N».
- Число ссылок или «Найдено N из M» и «Сбросить», если включены фильтры.
- Карточки ссылок, новые первыми.

Карточка ссылки показывает плитку с буквой домена в цвете коллекции, название
(открывает ссылку в новой вкладке), адрес без `https://`, описание (если
задано), теги и название коллекции. Клик по тегу включает фильтр по нему.
Действия на карточке: добавить в избранное или убрать из него, редактировать,
удалить. Кнопки редактирования и удаления появляются при наведении (на телефоне
видны всегда), удаление подтверждается прямо в карточке.

### 2. Избранное

Не отдельный экран, а переключатель «Все / Избранное» над списком. Он сочетается
с коллекцией, тегом и поиском.

На сервере избранное — это поле ссылки, а не отдельная сущность.

### 3. Коллекция

Клик по папке открывает коллекцию:

- папка темнеет, в заголовке название коллекции и число ссылок, над ним «< Моя
  библиотека» для возврата ко всем ссылкам;
- поиск, теги и избранное работают внутри коллекции;
- кнопка «Добавить ссылку» открывает форму, в которой текущая коллекция уже
  выбрана.

Меню ⋯ на папке:

- «Переименовать»: папка превращается в поле с названием. Enter сохраняет, Esc
  или клик мимо отменяют;
- «Удалить коллекцию»: открывает окно из пункта 5.

Новая коллекция создается так же, прямо на полке: «+ Новая коллекция» добавляет
в конец полки папку с полем для названия.

### 4. Окно «Добавить / изменить ссылку»

| Поле      | Обязательное | При редактировании              |
| --------- | ------------ | ------------------------------- |
| URL       | да           | не меняется                     |
| Название  | да           | можно изменить                  |
| Описание  | нет          | можно изменить                  |
| Коллекция | да           | можно изменить (перенос ссылки) |
| Теги      | нет          | можно изменить                  |
| Избранное | нет          | можно изменить                  |

- Коллекцию можно создать прямо в форме: «+ Новая коллекция». Она появляется на
  сервере только при сохранении ссылки, а если ссылку так и не сохранили,
  удаляется.
- Если коллекций нет, поле для новой коллекции открыто сразу. Если коллекция
  одна, она уже выбрана.
- Теги добавляются по Enter или запятой.
- Ошибки проверки показываются под полями.

При создании сервер проверяет, нет ли такой ссылки в библиотеке. Если есть,
открывается поп-ап из пункта 6.

### 5. Окно удаления коллекции

Если коллекция пустая:

> Удалить коллекцию «Development»? Это действие нельзя отменить. [Отмена]
> [Удалить]

Если в коллекции есть ссылки:

> Удалить «Development»? В коллекции 8 ссылок. Выбери, куда их перенести перед
> удалением. Перенести в: [Design] [AI] [University] [Отмена] [Перенести и >
> удалить]

Кнопка «Перенести и удалить» недоступна, пока не выбрана коллекция. Если других
коллекций нет, вместо списка подсказка: «Других коллекций нет. Сначала создай
еще одну, чтобы было куда перенести ссылки».

После выбора фронт вызывает `DELETE /collections/{id}?move_to={target_id}`. Если
удалили открытую коллекцию, открывается та, куда перенесли ссылки.

### 6. Поп-ап «Опа, такая ссылка уже есть»

Появляется, когда сервер отвечает `409 Conflict` на добавление ссылки.

Если ссылка уже лежит в выбранной в форме коллекции:

> Эта ссылка уже сохранена в коллекции «Development». [Закрыть] [Показать >
> ссылку]

«Показать ссылку» открывает эту коллекцию и подсвечивает существующую карточку.

Если ссылка лежит в другой коллекции:

> Эта ссылка уже сохранена в коллекции «University». Можно оставить ее там или
> перенести в «Development». Данные из формы не сохранятся. [Оставить там]
> [Перенести в «Development»]

«Перенести в …» вызывает `PATCH /links/{existing_link_id}` с
`{"collection_id": <выбранная коллекция>}`.

## Модель данных

### Collection

| Поле         | Тип      | Кто задает   | Правила                                                                      |
| ------------ | -------- | ------------ | ---------------------------------------------------------------------------- |
| `id`         | int      | сервер       | уникальный, никогда не используется повторно                                 |
| `name`       | str      | пользователь | 1–40 символов после удаления пробелов по краям; уникально без учета регистра |
| `created_at` | datetime | сервер       | время создания                                                               |
| `link_count` | int      | сервер       | вычисляется при ответе, не хранится                                          |

### Link

| Поле             | Тип          | Кто задает   | Правила                                                                        |
| ---------------- | ------------ | ------------ | ------------------------------------------------------------------------------ |
| `id`             | int          | сервер       | уникальный, никогда не используется повторно                                   |
| `url`            | str          | пользователь | обязательный; валидный http/https URL; после создания не меняется              |
| `normalized_url` | str          | сервер       | нормализованный URL для поиска дубликатов; хранится, в ответах API не отдается |
| `domain`         | str          | сервер       | домен из URL, например `react.dev`; для карточки                               |
| `title`          | str          | пользователь | обязательный, 1–120 символов                                                   |
| `description`    | str или null | пользователь | необязательный, до 500 символов                                                |
| `collection_id`  | int          | пользователь | обязательный; коллекция должна существовать                                    |
| `tags`           | list[str]    | пользователь | необязательный; правила в разделе «Теги»                                       |
| `favorite`       | bool         | пользователь | по умолчанию `false`                                                           |
| `created_at`     | datetime     | сервер       | время создания                                                                 |
| `updated_at`     | datetime     | сервер       | время последнего изменения                                                     |

Пример ссылки в ответе API:

```json
{
	"id": 14,
	"url": "https://fastapi.tiangolo.com/tutorial/",
	"domain": "fastapi.tiangolo.com",
	"title": "FastAPI Tutorial",
	"description": "Official FastAPI documentation",
	"collection_id": 2,
	"tags": ["fastapi", "python", "backend"],
	"favorite": false,
	"created_at": "2026-10-12T14:30:00Z",
	"updated_at": "2026-10-12T14:30:00Z"
}
```

Название коллекции для карточки фронт берет из `GET /collections` по
`collection_id`.

### Теги: GET /tags

Теги — не отдельная сущность. Сервер собирает их из всех ссылок и считает,
сколько ссылок у каждого тега. Сортировка: сначала самые частые, при равенстве —
по алфавиту.

```json
[
	{ "name": "react", "count": 5 },
	{ "name": "design", "count": 3 }
]
```

### Статистика: GET /stats

```json
{
	"total_links": 42,
	"favorite_links": 8,
	"total_collections": 4,
	"total_tags": 17
}
```

На фронте выводится в заголовке: «42 ссылки в 4 коллекциях».

## Решения

### 1. Ссылка всегда в коллекции

Ссылка принадлежит ровно одной коллекции. Если коллекций еще нет, форма сразу
предлагает создать новую: фронт сначала создает коллекцию, потом ссылку в ней.
Сервер отвечает `404` на несуществующий `collection_id`.

### 2. Коллекции

- Названия уникальны без учета регистра: `Development` и `development`
  одновременно существовать не могут. Правило действует и при создании, и при
  переименовании, нарушение дает `409`.
- Коллекции выводятся в порядке создания.

### 3. Удаление коллекции

- Пустая коллекция удаляется сразу: `204`.
- Непустая коллекция без `move_to` не удаляется: `409`, в ответе число ссылок в
  ней.
- `DELETE /collections/{id}?move_to={target_id}`: сервер переносит все ссылки в
  коллекцию `target_id`, затем удаляет исходную.
- Если `move_to` передан, он проверяется всегда: коллекции нет — `404`,
  совпадает с удаляемой — `400`.

### 4. Дубликаты ссылок

Один URL — одна ссылка во всей библиотеке. Перед сравнением URL нормализуется:

- регистр схемы и домена не учитывается;
- завершающий `/` не учитывается;
- якорь `#…` удаляется;
- параметры `utm_*` удаляются, остальные параметры сохраняются;
- регистр пути сохраняется: `/Learn` и `/learn` — разные страницы;
- `http` и `https` считаются разными адресами.

На дубликат сервер отвечает `409 Conflict`:

```json
{
	"detail": {
		"message": "Link already exists",
		"existing_link_id": 17,
		"collection_id": 3,
		"collection_name": "Development"
	}
}
```

### 5. Перенос дубликата

При «Перенести в …» у существующей ссылки меняется только `collection_id`. URL,
название, описание, теги, `favorite` и дата создания остаются прежними,
обновляется `updated_at`. То, что пользователь ввел в форме, отбрасывается.

### 6. URL не редактируется

`PATCH /links/{id}` не принимает поле `url`: запрос с ним получает `422`. Чтобы
сохранить другой адрес, создается новая ссылка.

### 7. Теги

Теги хранятся списком внутри ссылки. При сохранении:

- пробелы по краям удаляются;
- теги приводятся к нижнему регистру;
- пустые теги отбрасываются;
- повторы внутри одной ссылки убираются;
- длина тега — 1–30 символов.

`React`, `react` и `react` — один тег `react`.

### 8. Поиск

Поиск подстроки без учета регистра по названию, описанию, URL и тегам.
`GET /links?search=python` найдет и ссылку «Python Documentation», и ссылку с
тегом `python`.

### 9. Фильтры

Параметры `GET /links`: `search`, `tag`, `collection_id`, `favorite`. Несколько
параметров объединяются через «И». Фильтр по тегу работает без учета регистра.
Несуществующий `collection_id` дает `404`, а не пустой список.

### 10. Сортировка

Новые ссылки первыми: по `id` в порядке убывания. Редактирование не меняет место
ссылки в списке.

### 11. Удаление ссылки

Удаление окончательное: `204`. Удаленная или несуществующая ссылка дает `404`.

### 12. Идентификаторы

Номера ссылок и коллекций никогда не используются повторно. В каждом файле
данных хранится счетчик `next_id`, который только растет, даже после удалений.

GET /health → {"status": "ok"}
GET /version → {"version": "1.0.0"}

| Переменная     | Назначение                                         | По умолчанию                                  |
| -------------- | -------------------------------------------------- | --------------------------------------------- |
| `DATA_DIR`     | папка с файлами данных                             | `data`                                        |
| `LOG_LEVEL`    | уровень логов: `DEBUG`, `INFO`, `WARNING`, `ERROR` | `INFO`                                        |
| `CORS_ORIGINS` | адреса фронта, которым разрешено обращаться к API  | `http://localhost:3000,http://127.0.0.1:3000` |

В репозитории лежит `.env.example` с этими переменными. Настоящий `.env` в Git
не попадает. Приложение читает `.env` при запуске через
`uvicorn --env-file .env`, для этого нужен пакет `python-dotenv`.

### Хранение данных

```
data/
├── collections.json
└── links.json
```

Формат каждого файла:

```json
{
	"next_id": 15,
	"items": []
}
```

- Если файлов нет при запуске, они создаются пустыми, а в лог пишется событие.
- После каждого изменения файл перезаписывается целиком.
- Папка `data/` добавлена в `.gitignore`: личные ссылки не попадают в публичный
  репозиторий.
- В тестах `DATA_DIR` указывает на временную папку, поэтому тесты не трогают
  настоящую библиотеку и не зависят друг от друга.

### Логи

Логи выводятся в терминал, где запущено приложение. Примеры событий:

```
INFO     Application started: version=1.0.0, data_dir=data
INFO     Data files not found, created empty: data

INFO     Collection deleted: id=2, moved_links=8, to=3

```

Файлы бэкенда лежат в корне репозитория по списку из требований к проекту. Фронт
живет в отдельной папке и обращается к API по адресу из настроек, а разрешенные
адреса фронта задаются в `CORS_ORIGINS`.

## Фронтенд

- Стек: Next.js (App Router), React, TypeScript, Tailwind CSS.
- Данные загружаются в браузере: при открытии страницы фронт запрашивает
  `GET /collections`, `GET /links` и `GET /stats`, а при смене коллекции, тега,
  избранного или поиска — `GET /links` с фильтрами. Поиск отправляется через 250
  мс после последнего нажатия.
- После каждого изменения (ссылка, коллекция, избранное) библиотека загружается
  заново, поэтому числа на полке и в заголовке всегда совпадают с сервером.
- Адрес API задается переменной `NEXT_PUBLIC_API_URL`, по умолчанию
  `http://127.0.0.1:8000`.
- Раз в 30 секунд фронт вызывает `GET /health`: результат виден в шапке, а после
  восстановления связи библиотека загружается сама.
- Запросы и разбор ошибок собраны в `lib/api.ts`, состояние библиотеки и фильтры
  — в `lib/useLibrary.ts`.

## Деплой

- Ubuntu 24.04, оба процесса запускает и перезапускает systemd: `linkspace-api`
  (uvicorn, 127.0.0.1:8000) и `linkspace-web` (Next.js, 127.0.0.1:3000).
- Nginx принимает HTTPS на 443 и спрашивает логин и пароль: `/api/` уходит в
  API, остальное — в интерфейс. Без пароля открыт только `/api/health`.
- Фронт собирается с `NEXT_PUBLIC_API_URL=/api`, поэтому интерфейс и API живут
  на одном адресе и CORS не нужен.
- Данные лежат в `/var/lib/linkspace`, отдельно от кода.
- Если Nginx не может достучаться до API (`502`–`504`), фронт показывает тот же
  экран «Эх, сервер не отвечает...», что и при выключенном API на компьютере.

Пошаговая инструкция: [deploy.md](deploy.md).

## CI

GitHub Actions запускается при каждом `push` и `pull request`. Две задачи идут
параллельно.

**test** — бэкенд:

1. Устанавливает зависимости из `requirements-dev.txt`.
2. Запускает `python -m pytest -v`.
3. Если тесты прошли, сохраняет artifact `linkspace-app` с файлами бэкенда:
   `app_final.py`, `routers/`, `models.py`, `normalize.py`, `storage.py`,
   `requirements.txt`, `README.md`, `.env.example`.

**frontend** — интерфейс:

1. Ставит Node.js 24 и зависимости по `frontend/package-lock.json` (`npm ci`).
2. Запускает линтер: `npm run lint`.
3. Собирает проект: `npm run build`. Сборка заодно проверяет типы TypeScript и
   падает на любой ошибке.

## Тесты

Каждое решение из раздела «Решения» проверяется хотя бы одним тестом.

**Системные:**

- `/health` возвращает `ok`;
- `/version` возвращает версию.

**Коллекции:**

- создание коллекции дает `201`;
- название, отличающееся только регистром, дает `409`, в том числе при
  переименовании;
- пустая коллекция удаляется: `204`;
- удаление непустой коллекции без `move_to` дает `409`;
- удаление с `move_to` переносит ссылки в целевую коллекцию;
- несуществующий `move_to` дает `404`, `move_to`, равный удаляемой коллекции,
  дает `400`.

**Ссылки:**

- создание ссылки дает `201`, сервер заполняет `domain`, теги нормализованы;
- несуществующая коллекция дает `404`;
- некорректный URL дает `422`;
- повторный URL дает `409`, `existing_link_id` в ответе указывает на нужную
  ссылку;
- тот же URL в другом написании (`React.dev/learn/` и `react.dev/learn`) тоже
  дает `409`;
- `PATCH` с полем `url` дает `422`;
- запрос несуществующей ссылки дает `404`;
- удаленная ссылка после удаления дает `404`;
- номер удаленной ссылки не достается новой.

**Поиск и фильтры:**

- поиск без учета регистра находит ссылку и по названию, и по тегу;
- фильтр по тегу;
- фильтр по избранному;
- комбинация фильтров работает через «И»;
- несуществующий `collection_id` в фильтре дает `404`;
- новые ссылки идут первыми.

**Теги и статистика:**

- `/tags` считает ссылки по каждому тегу;
- `/stats` возвращает верные числа.
