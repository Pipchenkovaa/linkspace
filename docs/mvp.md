# LinkSpace MVP

## О проекте

**Суть.** LinkSpace — сервис для сохранения и организации полезных ссылок. Ссылки собираются в одном месте, распределяются по коллекциям, получают теги и отметку «избранное», а потом быстро находятся через поиск и фильтры.

**Для кого.** Для тех, кто регулярно сохраняет статьи, документацию, инструменты и учебные материалы и хочет держать их в структурированной библиотеке вместо десятков открытых вкладок и неразобранных закладок браузера.

**Какую проблему решает.** Ссылку легко сохранить, но зачастую потом очень сложно найти.

## Границы MVP

Входит: ссылки, коллекции, теги, избранное, поиск и фильтры, статистика библиотеки.

Не входит:

- авторизация и несколько пользователей: сервис рассчитан на одного человека;
- автоматическое получение названия, описания и картинки сайта: пользователь вводит их сам;
- редактирование URL: другой адрес — это новая ссылка;
- корзина: удаление окончательное;
- пагинация: все ссылки отдаются одним списком;
- база данных: данные хранятся в JSON-файлах.

## Экраны

### 1. Библиотека

Главный экран со всеми ссылками.

- Боковая панель: список коллекций с числом ссылок в каждой, кнопка «Создать коллекцию», пункт «Избранное».
- Строка поиска.
- Фильтр по тегам.
- Число найденных ссылок.
- Кнопка «Добавить ссылку».
- Карточки ссылок, новые первыми.

Карточка ссылки показывает название, домен, описание (если задано), теги, название коллекции и отметку избранного. Действия на карточке: добавить в избранное или убрать из него, редактировать, удалить.

### 2. Избранное

Все ссылки с `favorite = true`. Устроен так же, как библиотека: поиск, фильтр по тегам и коллекциям, карточки с теми же действиями.

На сервере избранное — это поле ссылки, а не отдельная сущность.

### 3. Коллекция

Экран одной коллекции:

- название коллекции и число ссылок в ней;
- поиск и фильтр по тегам внутри коллекции;
- карточки ссылок этой коллекции;
- кнопка «Добавить ссылку», в форме которой текущая коллекция уже выбрана;
- переименование коллекции;
- удаление коллекции.

### 4. Окно «Добавить / изменить ссылку»

| Поле | Обязательное | При редактировании |
|---|---|---|
| URL | да | не меняется |
| Название | да | можно изменить |
| Описание | нет | можно изменить |
| Коллекция | да | можно изменить (перенос ссылки) |
| Теги | нет | можно изменить |
| Избранное | нет | можно изменить |

При создании сервер проверяет, нет ли такой ссылки в библиотеке. Если есть, открывается поп-ап из пункта 6.

### 5. Окно удаления коллекции

Если коллекция пустая:

> Удалить коллекцию «Development»? Это действие нельзя отменить.
> [Отмена] [Удалить]

Если в коллекции есть ссылки:

> В коллекции «Development» 8 ссылок. Выберите, куда их перенести перед удалением.
> Перенести в: [Design ▾]
> [Отмена] [Перенести и удалить]

После выбора фронт вызывает `DELETE /collections/{id}?move_to={target_id}`.

### 6. Поп-ап «Такая ссылка уже есть»

Появляется, когда сервер отвечает `409 Conflict` на добавление ссылки.

Если ссылка уже лежит в текущей коллекции:

> Эта ссылка уже сохранена в коллекции «Development».
> [Показать ссылку] [Закрыть]

«Показать ссылку» подсвечивает существующую карточку.

Если ссылка лежит в другой коллекции:

> Эта ссылка уже сохранена в коллекции «University».
> [Оставить там] [Перенести сюда]

«Перенести сюда» вызывает `PATCH /links/{existing_link_id}` с `{"collection_id": <текущая коллекция>}`.

### 7. Пустые состояния

| Ситуация | Текст | Действие |
|---|---|---|
| Нет ни одной коллекции | У вас пока нет коллекций. Создайте первую, чтобы начать сохранять ссылки. | Создать коллекцию. Кнопка «Добавить ссылку» недоступна |
| В библиотеке нет ссылок | Здесь пока нет ссылок. Сохраните первый полезный ресурс. | Добавить ссылку |
| В коллекции нет ссылок | В этой коллекции пока ничего нет. | Добавить ссылку |
| В избранном пусто | Отмечайте важные ссылки звездочкой, чтобы быстро находить их здесь. | — |
| Поиск и фильтры ничего не нашли | Ничего не найдено. Измените запрос или сбросьте фильтры. | Сбросить фильтры |

### 8. Ошибки

| Код | Когда | Что видит пользователь |
|---|---|---|
| 400 | Некорректная операция, например перенос ссылок в удаляемую коллекцию | Сообщение в диалоге |
| 404 | Ссылка или коллекция не существует | Сообщение рядом с действием |
| 409 | Дубликат URL, повторяющееся название коллекции, удаление непустой коллекции без переноса | Поп-ап или сообщение в диалоге |
| 422 | Данные не прошли проверку | Подсказка у поля формы |
| 500 | Неожиданная ошибка сервера | «Что-то пошло не так. Не удалось выполнить действие. Попробуйте еще раз.» |

| `GET /tags` | 200 | — |
| `GET /stats` | 200 | — |

## Модель данных

### Collection

| Поле | Тип | Кто задает | Правила |
|---|---|---|---|
| `id` | int | сервер | уникальный, никогда не используется повторно |
| `name` | str | пользователь | 1–40 символов после удаления пробелов по краям; уникально без учета регистра |
| `created_at` | datetime | сервер | время создания |
| `link_count` | int | сервер | вычисляется при ответе, не хранится |

### Link

| Поле | Тип | Кто задает | Правила |
|---|---|---|---|
| `id` | int | сервер | уникальный, никогда не используется повторно |
| `url` | str | пользователь | обязательный; валидный http/https URL; после создания не меняется |
| `normalized_url` | str | сервер | нормализованный URL для поиска дубликатов; хранится, в ответах API не отдается |
| `domain` | str | сервер | домен из URL, например `react.dev`; для карточки |
| `title` | str | пользователь | обязательный, 1–120 символов |
| `description` | str или null | пользователь | необязательный, до 500 символов |
| `collection_id` | int | пользователь | обязательный; коллекция должна существовать |
| `tags` | list[str] | пользователь | необязательный; правила в разделе «Теги» |
| `favorite` | bool | пользователь | по умолчанию `false` |
| `created_at` | datetime | сервер | время создания |
| `updated_at` | datetime | сервер | время последнего изменения |

Пример ссылки в ответе API:

```json
{
  "id": 14,
  "url": "https://fastapi.tiangolo.com/tutorial/",
  "domain": "fastapi.tiangolo.com",
  "title": "FastAPI Tutorial",
  "description": "Official FastAPI documentation",
  "collection_id": 2,
  "tags": ["fastapi", "python", "backend"],
  "favorite": false,
  "created_at": "2026-10-12T14:30:00Z",
  "updated_at": "2026-10-12T14:30:00Z"
}
```

Название коллекции для карточки фронт берет из `GET /collections` по `collection_id`.

### Теги: GET /tags

Теги — не отдельная сущность. Сервер собирает их из всех ссылок и считает, сколько ссылок у каждого тега. Сортировка: сначала самые частые, при равенстве — по алфавиту.

```json
[
  {"name": "react", "count": 5},
  {"name": "design", "count": 3}
]
```

### Статистика: GET /stats

```json
{
  "total_links": 42,
  "favorite_links": 8,
  "total_collections": 4,
  "total_tags": 17
}
```

На фронте выводится строкой под заголовком: «42 ссылки, 4 коллекции, 8 в избранном».

## Решения

### 1. Ссылка всегда в коллекции

Ссылка принадлежит ровно одной коллекции. Пока коллекций нет, ссылку добавить нельзя: фронт блокирует кнопку, а сервер отвечает `404` на несуществующий `collection_id`.

### 2. Коллекции

- Названия уникальны без учета регистра: `Development` и `development` одновременно существовать не могут. Правило действует и при создании, и при переименовании, нарушение дает `409`.
- Коллекции выводятся в порядке создания.

### 3. Удаление коллекции

- Пустая коллекция удаляется сразу: `204`.
- Непустая коллекция без `move_to` не удаляется: `409`, в ответе число ссылок в ней.
- `DELETE /collections/{id}?move_to={target_id}`: сервер переносит все ссылки в коллекцию `target_id`, затем удаляет исходную.
- Если `move_to` передан, он проверяется всегда: коллекции нет — `404`, совпадает с удаляемой — `400`.

### 4. Дубликаты ссылок

Один URL — одна ссылка во всей библиотеке. Перед сравнением URL нормализуется:

- регистр схемы и домена не учитывается;
- завершающий `/` не учитывается;
- якорь `#…` удаляется;
- параметры `utm_*` удаляются, остальные параметры сохраняются;
- регистр пути сохраняется: `/Learn` и `/learn` — разные страницы;
- `http` и `https` считаются разными адресами.

На дубликат сервер отвечает `409 Conflict`:

```json
{
  "detail": {
    "message": "Link already exists",
    "existing_link_id": 17,
    "collection_id": 3,
    "collection_name": "Development"
  }
}
```

### 5. Перенос дубликата

При «Перенести сюда» у существующей ссылки меняется только `collection_id`. URL, название, описание, теги, `favorite` и дата создания остаются прежними, обновляется `updated_at`. То, что пользователь ввел в форме, отбрасывается.

### 6. URL не редактируется

`PATCH /links/{id}` не принимает поле `url`: запрос с ним получает `422`. Чтобы сохранить другой адрес, создается новая ссылка.

### 7. Теги

Теги хранятся списком внутри ссылки. При сохранении:

- пробелы по краям удаляются;
- теги приводятся к нижнему регистру;
- пустые теги отбрасываются;
- повторы внутри одной ссылки убираются;
- длина тега — 1–30 символов.

`React`, ` react ` и `react` — один тег `react`.

### 8. Поиск

Поиск подстроки без учета регистра по названию, описанию, URL и тегам. `GET /links?search=python` найдет и ссылку «Python Documentation», и ссылку с тегом `python`.

### 9. Фильтры

Параметры `GET /links`: `search`, `tag`, `collection_id`, `favorite`. Несколько параметров объединяются через «И». Фильтр по тегу работает без учета регистра. Несуществующий `collection_id` дает `404`, а не пустой список.

### 10. Сортировка

Новые ссылки первыми: по `id` в порядке убывания. Редактирование не меняет место ссылки в списке.

### 11. Удаление ссылки

Удаление окончательное: `204`. Удаленная или несуществующая ссылка дает `404`.

### 12. Идентификаторы

Номера ссылок и коллекций никогда не используются повторно. В каждом файле данных хранится счетчик `next_id`, который только растет, даже после удалений.

## Системная часть

### /health и /version

```json
GET /health   →  {"status": "ok"}
GET /version  →  {"version": "1.0.0"}
```

Версия хранится в коде, константой `VERSION` в `app_final.py`.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATA_DIR` | папка с файлами данных | `data` |
| `LOG_LEVEL` | уровень логов: `DEBUG`, `INFO`, `WARNING` | `INFO` |
| `CORS_ORIGINS` | адреса фронта, которым разрешено обращаться к API | `http://localhost:3000` |

В репозитории лежит `.env.example` с этими переменными. Настоящий `.env` в Git не попадает. Приложение читает `.env` при запуске через `uvicorn --env-file .env`, для этого нужен пакет `python-dotenv`.

### Хранение данных

```
data/
├── collections.json
└── links.json
```

Формат каждого файла:

```json
{
  "next_id": 15,
  "items": []
}
```

- Если файлов нет при запуске, они создаются пустыми, а в лог пишется событие.
- После каждого изменения файл перезаписывается целиком.
- Папка `data/` добавлена в `.gitignore`: личные ссылки не попадают в публичный репозиторий.
- В тестах `DATA_DIR` указывает на временную папку, поэтому тесты не трогают настоящую библиотеку и не зависят друг от друга.

### Логи

Логи выводятся в терминал, где запущено приложение. Примеры событий:

```
INFO     Application started: version=1.0.0, data_dir=data
INFO     Data files not found, created empty: data
INFO     Collection created: id=3
INFO     Collection deleted: id=2, moved_links=8, to=3
INFO     Link created: id=14
INFO     Link moved: id=14, collection_id=2
INFO     Search: query="react", results=5
WARNING  Duplicate link: existing_id=14
WARNING  Collection not found: id=99
ERROR    Unexpected error: <описание>
```

## CI

GitHub Actions запускается при каждом `push` и `pull request`:

1. Устанавливает зависимости из `requirements-dev.txt`.
2. Запускает `python -m pytest -v`.
3. Если тесты прошли, сохраняет artifact с файлами приложения: `app_final.py`, `requirements.txt`, `README.md`, `.env.example`.

## Тесты

Каждое решение из раздела «Решения» проверяется хотя бы одним тестом.

**Системные:**

- `/health` возвращает `ok`;
- `/version` возвращает версию.

**Коллекции:**

- создание коллекции дает `201`;
- название, отличающееся только регистром, дает `409`, в том числе при переименовании;
- пустая коллекция удаляется: `204`;
- удаление непустой коллекции без `move_to` дает `409`;
- удаление с `move_to` переносит ссылки в целевую коллекцию;
- несуществующий `move_to` дает `404`, `move_to`, равный удаляемой коллекции, дает `400`.

**Ссылки:**

- создание ссылки дает `201`, сервер заполняет `domain`, теги нормализованы;
- несуществующая коллекция дает `404`;
- некорректный URL дает `422`;
- повторный URL дает `409`, `existing_link_id` в ответе указывает на нужную ссылку;
- тот же URL в другом написании (`React.dev/learn/` и `react.dev/learn`) тоже дает `409`;
- `PATCH` с полем `url` дает `422`;
- запрос несуществующей ссылки дает `404`;
- удаленная ссылка после удаления дает `404`;
- номер удаленной ссылки не достается новой.

**Поиск и фильтры:**

- поиск без учета регистра находит ссылку и по названию, и по тегу;
- фильтр по тегу;
- фильтр по избранному;
- комбинация фильтров работает через «И»;
- несуществующий `collection_id` в фильтре дает `404`;
- новые ссылки идут первыми.

**Теги и статистика:**

- `/tags` считает ссылки по каждому тегу;
- `/stats` возвращает верные числа.
